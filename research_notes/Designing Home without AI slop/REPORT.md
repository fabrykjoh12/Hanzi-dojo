# Stop decorating Home; compose it instead

**The fix for "AI slop" on HanziDojo's Home is a better brief and a better loop, more than a better skill.** Every rejected mockup used a pattern for its own sake: a vermilion block, a giant stat with a red button, frosted glass, a progress ring, a decorative seal, a costume rice-paper frame. Anthropic attributes this to "distributional convergence". Models fall back to the "high-probability center" ([Anthropic](https://claude.com/resources/articles/improving-frontend-design-through-skills)), and current Claude models have a persistent house style of cream, serif and terracotta that sits uncomfortably close to vermilion `#B83A24` on HanziDojo's warm off-white ([Opus 4.8 prompting guide](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-opus-4-8)). The approaches with the best evidence share a sequence. Write a concrete positive brief rooted in the subject. Generate three or four substantively different directions before building anything. Render them at phone width. Have a separate, sceptical reviewer critique them. Then do the final polish by hand. For tools, take Anthropic's official `frontend-design` skill as the checklist and Impeccable's `critique`/`quieter`/`distill`/`polish` for refinement, and run Playwright, which is already in the repo, for screenshots. Where any skill's taste disagrees with CLAUDE.md or docs/DESIGN-BIBLE.md, the house docs win. The design move this report recommends is a quiet, opaque, off-centre surface sitting in the empty mist of the ink scene (liúbái, 留白). It leads with a sentence ("38 reviews waiting"), not a hero number, and shows progress as a hairline or a plain fraction. The one memorable element is the learner's own Chinese, not ornament.

## Eight tools ranked, and only three worth installing now

The official tools come first. Anthropic's `frontend-design` plugin is installed with `/plugin install frontend-design@claude-plugins-official`. The broader `anthropics/skills` repo, with about 193k stars, is installed with `/plugin marketplace add anthropics/skills` ([anthropics/skills](https://github.com/anthropics/skills); [claude-plugins-official](https://github.com/anthropics/claude-plugins-official)). The current SKILL.md is a real process, not a vibe. It asks for a written plan of **4–6 named hex values, typefaces and ASCII wireframes**. It then has Claude review that plan for genericness before any code exists ("spend your boldness in one place"), and it ends with "remove one element before finishing" ([SKILL.md](https://raw.githubusercontent.com/anthropics/claude-plugins-official/main/plugins/frontend-design/skills/frontend-design/SKILL.md)). Its siblings `canvas-design`, `theme-factory`, `brand-guidelines` and `algorithmic-art` target posters and artifacts, and add little to in-app React UI.

Among community skills, **Impeccable** (`pbakaus/impeccable`, about 108k stars) fits best because it refines rather than imposes a style. It has named steer commands (`quieter`, `distill`, `bolder`) and review commands (`critique`, `audit`, `polish`). It also ships a deterministic **62-rule slop detector** that needs no LLM, and an `init`/`document` step that writes the product and visual system into files every later command reads ([Impeccable](https://github.com/pbakaus/impeccable)). Install it with `/plugin marketplace add pbakaus/impeccable` or `npx impeccable install`. The second option can add a hook, which is code that runs automatically, so review it before accepting. UI UX Pro Max (about 148k stars) generates whole design systems from a catalog of 192 palettes and 74 font pairings ([repo](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill)). HanziDojo already has a design system, so that output would compete with the Design Bible.

The trust caveats are real. Snyk scanned **3,984 skills on the ClawHub registry, found 76 with confirmed malicious payloads and found that 36.8% had some security issue**, and noted that skills "operate with the full permissions of the AI agent" ([Snyk ToxicSkills](https://snyk.io/blog/toxicskills-malicious-ai-agent-skills-clawhub/)). Anthropic's own marketplace README says it does not control what partner or community plugins contain ([claude-plugins-official](https://github.com/anthropics/claude-plugins-official)). Star counts of 100k+ show virality, not quality. No independent quality evaluation of any design skill exists, and last-commit dates could not be verified for any repo. Follow the repo's existing practice: vendor a pinned, read copy into `.claude/skills/`, record it in `VENDORED.md` with a note subordinating it to CLAUDE.md, and run the repo's `security-scan` skill over it. Vendored copies also work in cloud sessions, where `~/.claude/plugins` does not persist.

Several skill preferences conflict with the house rules, and the house rules win each time. `frontend-design` and the Anthropic cookbook warn against Inter and push a distinctive webfont, and the cookbook adds "size jumps of 3x+" and atmospheric layered backgrounds ([cookbook](https://platform.claude.com/cookbook/coding-prompting-for-frontend-aesthetics)). The Design Bible §5 fixes the type to Inter and Noto Sans SC, bans "oversized numerals", and CLAUDE.md requires that the native build never contact Google Fonts. The skill also lists "near-black with a single vermilion accent" and "warm cream + terracotta" as clichés, yet it says "the brief's own words always win". The vermilion accent is brand, not slop. What is risky is pairing it with a serif display, italic word accents, ALL-CAPS eyebrows and middle-dot meta strings. Most community skills also assume Tailwind and TypeScript, which conflicts with CLAUDE.md §6. The sharpest internal conflict is in the Design Bible itself. Its §14 lists "ink washes and background illustration used to make a weak screen look interesting" as an anti-pattern. The owner's ink background is legitimate only if the screen would be strong without it, with the art doing compositional work rather than propping things up.

## Designers diverge wide, then critique against a render

The best-attested workflow comes from Nate Parrott, the Anthropic designer who built Claude Design. He asks for wireframes first, generates many options ("most of them won't be good, and that's fine"), then remixes the pieces he likes: "I like option B and a little of option D. Give me five riffs that smoosh those together." He supplies photographed sketches and moodboards, connects the real codebase so Claude reuses existing components, and does the final sizing by hand because it is "better eyeballed anyway" ([Claude article](https://claude.com/ko/resources/articles/how-the-product-designer-who-built-claude-design-uses-it-to-explore-ideas-before-building-them)). That is the opposite of what produced the six rejections, which was one mockup at a time, each judged whole.

Anthropic's guidance explains why "don't make it generic" fails. Negative instructions "tend to shift the model to a different fixed palette rather than producing variety". The two methods that work are specifying a concrete alternative, or asking the model to **"propose 4 distinct visual directions… each as bg hex / accent hex / typeface — one-line rationale"** and building only the chosen one ([Opus 4.8 guide](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-opus-4-8)). The worked example in that guide describes atmosphere in material terms ("misted metallic surface"), with an exact radius and exact motion timing. For HanziDojo the equivalent vocabulary is ink, mist, paper and the learner's own words.

The critique has to come from a reviewer separate from the generator. In Anthropic's generator/evaluator experiment, agents "reliably skew positive when grading their own work". A separate, sceptical evaluator that drove Playwright on the live page was easier to tune. It scored **design quality, originality, craft and functionality** over 5–15 iterations, deciding each time whether to refine or pivot, and loaded wording such as "museum quality" pulled every output toward one look ([Anthropic Engineering](https://www.anthropic.com/engineering/harness-design-long-running-apps)). Claude Code's own best practices say the same: paste screenshots instead of describing them, and demand the rendered screenshot as evidence ([best practices](https://code.claude.com/docs/en/best-practices.md)). References should be used for specific properties: say what to borrow (spacing, hierarchy) and what to leave out (colour, copy), one reference per screen, and ask for a proposed policy before any build (community guidance via snippets, weak evidence; [Mobbin agent guidance](https://mobbin.com/llms-full.txt)). HanziDojo's `docs/REVIEWER-PROTOCOL.md` already defines a fresh-context reviewer, which is the right vehicle for this.

## Six rejections, one diagnosis: surfaces standing in for hierarchy

Each rejected mockup matches a catalogued tell. A big vermilion block is the Design Bible's "giant accent blocks". The white card with a giant number and a red button is the "big number + small label" template the skill names. Frosted glass on a content surface is "generic glassmorphism", which the Design Bible §6 reserves for system layers. The ink ring is a decorative progress widget. The seal, rice-paper frame and vertical text are motif as costume. Kitsch is defined by "excessive garishness or sentimentality", and motifs read as intentional only "when used sparingly" ([Kittl](https://www.kittl.com/blogs/design-styles-name-stl/)). Faux-brush "chop suey" styling is widely read as Orientalist ([Wikipedia: Wonton font](https://en.wikipedia.org/wiki/Wonton_font)). The ban lists give concrete replacements. Use a hairline or `0 1px 3px` in place of `0 20px 60px` shadows. Allow at most one glass element, "only where translucency has a purpose". Vary radius by role. Keep motion at 100–150ms for routine changes and 200–300ms for significant ones. Write specific numbers rather than round ones ([Laith0003 ban list](https://github.com/Laith0003/ux-skill/wiki/Anti-AI-slop-ban-list)).

What replaces the tells is craft that rarely shows in a screenshot. Use **tabular numerals** for counters, a nested radius (inner = outer − padding), tonal elevation in dark mode instead of shadow, and contrast floors of 4.5:1 for body text ([styleseed VISUAL-CRAFT](https://github.com/bitjaru/styleseed/blob/main/engine/VISUAL-CRAFT.md)). Refactoring UI makes the key point for a count: "labels are a last resort". "12 left in stock" beats "In stock: 12" ([Refactoring UI](https://www.refactoringui.com/previews/labels-are-a-last-resort)). The authentic Chinese aesthetic idea to borrow is compositional: **留白 liúbái, deliberately unpainted space treated as meaningful** ([Contextual Chinese](https://contextualchinese.com/%E7%95%99%E7%99%BD)). The Design Bible already says "Emptiness is allowed to be empty". Two warnings apply. "The failure mode of every anti-slop effort is replacing one default look with another" (prg.sh, via search snippet only). Most of this literature is practitioner consensus, not measured fact.

## Award-winning calm apps tie the scene to state

The strongest primary-source precedents are Apple Design Award citations. **Tide Guide (ADA 2026, Visuals and Graphics)** has a palette "designed to match the color of the sky throughout the day". Primary "wisely gets out of the way of the news". Gentler Streak's summaries are "less about hard comparisons and more about progress" ([ADA 2026](https://developer.apple.com/design/awards/); [ADA 2024](https://developer.apple.com/design/awards/2024/)). The learning app Vocabulary was a 2025 finalist for "charming, consistent illustrations" with typography that feels "modern and balanced", and Lumy was a finalist for "a carefully curated color palette" ([ADA 2025](https://developer.apple.com/design/awards/2025/)). Apple Weather's backgrounds show the actual sun position and conditions, with the data in sectioned modules on top ([MacRumors](https://www.macrumors.com/guide/ios-15-weather-app/)). Opal's brand kit forbids overlaying text on its hero art, so the text sits beside it ([Opal brand kit](https://brandkit.opal.so)). Duolingo's 2022 home became one path because learners were unsure what to do next ([Duolingo](https://blog.duolingo.com/new-duolingo-home-screen-design/)). Among Chinese-learning apps, Du Chinese is praised for being "clean, intuitive" and content-first, not for illustration ([Go East Mandarin](https://goeastmandarin.com/du-chinese-review/)).

These precedents point to three rules. The background earns its place by carrying meaning, such as time of day or state, not as wallpaper. Text stays out of the art's focal area. The home offers one obvious next action. There are gaps. No source documents how Calm or Headspace put cards over their scenes, nothing sourced covers dark-mode heroes, and Mobbin's coverage of these apps is unconfirmed. Useful Mobbin searches are Tide Guide, Lumy, Moonlitt, Gentler Streak, Structured, Opal, Headspace and Du Chinese, filtered to "Home" or "Today".

## A Home spec and a five-step process for the next round

The concrete spec is synthesis, not a quoted source. **Compose the art around the card rather than the card onto the art.** Crop or regenerate `bg-chinese.webp` (Higgsfield is pre-approved) so it has a deliberate band of empty mist where the card sits, and let the mist fade into `--bg` as a natural scrim. Keep the peaks free of text, as Opal does. Place the card off-centre, for example in the lower third, with left-aligned text, and leave the sky empty. The surface is an opaque `--surface` or a slight paper mix, with a 1px `--hairline`, `--shadow-1` in light mode and tonal elevation in dark mode. It uses one radius from the Bible's scale (~20px for a major object) and no glass. The content leads with a sentence in Inter with tabular numerals at title size, such as "38 reviews waiting · about 9 min". Avoid the middle-dot if it reads as template chrome; the skill flags that pattern. Progress is a fine hairline bar or a plain fraction ("412 of 600 words toward HSK 4"). Vermilion appears only in the progress fill. The whole card is the tap target, so there is no red button, only a quiet chevron or the sentence itself as the affordance. If one element is to be memorable, make it real Chinese: a word the learner learned yesterday or the title of the story they can now read, set in Noto Sans SC. That honours "the Chinese should visually dominate" without becoming watermark Hanzi. Allow at most one entrance under 300ms using opacity and transform, and nothing under reduced motion. An optional later step is to shift the scene's tone with time of day, as Tide Guide does.

The process has five steps. First, write a one-page Home brief covering audience, the one job, the one memorable thing, the house constraints and the six rejected looks with the reason for each, so Claude has concrete positives and named exclusions rather than "don't be generic". Second, ask for **four directions as ASCII wireframes plus a one-line rationale**, each differing in composition rather than colour, and pick fragments. Third, build only the chosen direction behind the existing Home and render it with Playwright at 320, 390 and 430 widths in both themes, laid out side by side so the owner can judge at a glance. Fourth, run a fresh-context reviewer per `docs/REVIEWER-PROTOCOL.md`, using Anthropic's four criteria, the `frontend-design` tell list and the Design Bible §14 anti-patterns. Check card-text contrast at 4.5:1 over the real illustration pixels and at large Dynamic Type. Use Impeccable `quieter`/`distill` if it is vendored. Fifth, hand-polish sizes and spacing directly, then put the logic through `npm run verify:pr`, with any layout logic extracted into a tested module such as `homePresentation.js`.

## Conclusion

None of the six rejected mockups was badly drawn. Each answered the wrong question: what could this card look like, rather than what should be left out. The research reframes the task from styling a card to composing a scene, where empty mist is the design element and the learner's own Chinese is the one thing allowed to shine. That also resolves the apparent clash with the Design Bible's ban on background ink washes. The ban targets art used to rescue a weak screen, and art composed around the screen's single job is a different thing. The skills and MCPs are useful scaffolding, but the evidence is clear that they work only with a written brief, wide divergence and a critic that is not the generator. Without those, any skill simply produces its own house style.
